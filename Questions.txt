 **More constrained:**

 > "Here are 10 things our platform supports. Configure them in different ways."

 Context Control seems to be **somewhere in between**.

 - What kinds of agents can you create?

 **Level 1 — Automation platform**

 > "Choose an agent → connect Gmail → give it a prompt → schedule it."

 Useful, but relatively constrained.

 **Level 2 — Agent development platform**

 > "Create agents → create teams → give them arbitrary external tools → create custom MCP servers → build persistent workflows."

 **Level 3 — AI infrastructure / operating layer**

 > "I can create arbitrary software capabilities, expose them as tools, dynamically create agents, have agents create/modify other agents, maintain persistent state, interact with my databases/APIs, and build an entire application on top of it."

 **This is the level I suspect you're trying to determine whether Context Control reaches.**
### Assessment Based on Implementation

Now that we have built and verified the platform, I can answer these questions directly:

| Area | The Reality of Context Control |
| --- | --- |
| **Agent Session Studio** | Agents are highly customizable through Context Profiles (system instructions, brand voice, token budgets, tools). They operate as LLM-driven nodes connecting to MCP tools, rather than executing arbitrary un-sandboxed code. |
| **Team Builder** | Yes. It features a visual builder for multi-agent supervisor graphs, allowing hierarchical task routing and dynamic worker delegation. |
| **MCP Hub** | Highly extensible. You can connect both predefined tool spokes (Gmail, Slack, etc.) AND custom MCP servers of your own making. |
| **Custom MCP** | Fully supported. It includes a standardized Platform MCP Controller endpoint (Stdio/SSE) so you can host servers yourself and plug them in. |
| **Skills Library** | Yes, it has a Skills Library Registry for modular agent skill packages and specialized automation kits. |
| **Developer API** | It exposes a Tenant REST API with a live cURL request generator, allowing programmatic control over workflows. |
| **Platform MCP Controller** | Yes, this acts as the bridge connecting external hosts (like Claude Desktop or Cursor) to the platform's agents and tools. |
| **Knowledge/RAG** | Supported natively. Allows document and URL knowledge base ingestion with high-dimensional vector embeddings stored in Supabase pgvector. |
| **Persistent state** | Extremely robust. Uses PostgreSQL to maintain a persistent thread viewer storing binary state checkpoints, message history, and audit logs. |
| **Scheduler** | Built-in Task Calendar backed by BullMQ Deferred Queue and AWS EventBridge for durable countdown triggers, plus recurring heartbeats. |
| **Security/permissions** | Enterprise-grade. Uses an AES-256-GCM encrypted BYOK vault and database Row-Level Security (RLS) sandboxing for all operations. |
| **Voice/telephony** | Integrates ElevenLabs Voice & Twilio Telephony for autonomous voice calls, including full audit transcripts and programmatic control. |
| **Sandbox/testing** | Includes a Test Simulator and Time-Travel Sandbox to safely simulate graph transitions and tool failures before production. |
| **Deployment** | Currently designed as a SaaS platform. While it relies on modern open-source foundations (Next.js, Supabase), self-hosting it entirely would require deploying the full stack manually. |
| **Limits** | Controlled via Context Profiles & Token Budgeting, which enforce tenant-level token and execution limits to prevent runaway costs. |

**Conclusion**: Context Control firmly sits at **Level 3 — AI infrastructure / operating layer**. With custom MCP, Developer APIs, persistent state (checkpoints), pgvector knowledge bases, and complex routing graphs, you can build an entire autonomous application on top of it.
